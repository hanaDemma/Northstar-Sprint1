
# Project Setup

## Project

**Northstar Support Deflection MVP**

## GitHub Repository

**Repository:** `Northstar-Sprint1`

The GitHub repository was created to host the project's source code, documentation, and collaborative development work.

## GitHub Project Board

A GitHub Project board was created to manage team tasks, assign responsibilities, and track project progress.

The project board provides visibility into the team's work and supports an auditable workflow from task creation to completion.

## Task Management Workflow

Tasks are organized using the following workflow:

* **Backlog** – Tasks that have been identified but are not yet ready to start.
* **Ready** – Tasks that are clearly defined and ready for development.
* **In Progress** – Tasks currently being worked on.
* **Review** – Completed development work waiting for review.
* **Done** – Tasks that have been reviewed and completed.

## Task Assignment

Tasks are assigned to individual team members based on their responsibilities and areas of contribution.

Each task should include:

* A clear task description
* An assigned team member
* A project status
* A defined expected outcome
* A corresponding GitHub Issue where appropriate

## Branch Naming Convention

The team follows a consistent branch naming convention:

* `feature/<task-name>` – New functionality or feature development
* `chore/<task-name>` – Project setup, configuration, documentation, or maintenance
* `fix/<task-name>` – Bug fixes

### Examples

* `feature/order-status-flow`
* `chore/project-setup`
* `fix/order-lookup`

## Commit Convention

Commits use clear and descriptive messages to make the development history easy to understand and audit.

### Examples

* `feat: add order status flow`
* `chore: set up project board`
* `docs: update project documentation`
* `fix: resolve order lookup issue`

## Collaboration Workflow

The team follows the following GitHub workflow:

1. Create or select a GitHub Issue.
2. Add the task to the GitHub Project board.
3. Assign the task to the responsible team member.
4. Move the task to **Ready** when it is prepared for development.
5. Create a dedicated branch for the task.
6. Implement the task using VS Code.
7. Commit changes using a descriptive commit message.
8. Push the branch to GitHub.
9. Create a Pull Request.
10. Review the changes.
11. Address review comments if required.
12. Merge the Pull Request into the `main` branch.
13. Move the corresponding Project task to **Done**.

## Project Setup Contribution

The repository and project management environment were configured to support collaborative development.

The setup included:

* GitHub repository configuration
* GitHub Project board creation
* Task organization
* Task assignment to team members
* Definition of project workflow statuses
* Branch naming conventions
* Commit message conventions
* Collaborative Pull Request workflow

This setup provides a clear and traceable record of team activities and individual contributions throughout the project.

## Audit Trail

Project activities are tracked through GitHub Issues, Project board status changes, branches, commits, Pull Requests, and merged changes.

This workflow helps demonstrate individual contributions and provides an auditable history of the team's collaborative development process.
